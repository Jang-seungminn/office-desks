# od-core parity checklist (R1)

`od-core` ports the Node core in `bridge/src` (everything except `tui/`). TS is the spec; JSON goldens
(`tests/golden/*.json`, generated by `npm run golden` from `bridge/scripts/golden.ts`) pin the wire shapes and Korean
messages. Unit tests live next to the code (`#[cfg(test)]` in `src/`); integration tests are in `tests/`.

Legend: **done** = ported in R1. **R2/R3/R5** = deliberately left for that milestone.

## Deliberate differences

Hook relay and Windows command line (called out by the plan):

- Hook relay is our own binary: `relay_command(exe)` returns `[exe, "hook-relay"]` instead of node plus `relayScript()`; there is no `relayScript` or its file-exists test. Reason: no Node at runtime.
- `NativeDeps.relay` is a single argv `Vec<String>` (TS: `relay` plus `node`). Reason: same.
- Hook command quoting also backslash-escapes `"`, `$` and backtick (TS only wraps in quotes and turns `\` into `/`). Output is identical for ordinary paths. Reason: safe against injection; Claude runs hooks via sh/Git Bash, so quoting is POSIX-only by design.
- `hook_relay::run` abandons its worker thread on the 3 s overall timeout; the binary must exit right after. Reason: no thread cancellation in std.
- Windows command line: `windows_command_line` reproduces the `append_quoted` rules portable-pty passes to CreateProcessW (node-pty did this inside its own layer). Reason: different PTY library; every TS vector is pinned.
- `windows_cmd_exe` picks `%ComSpec%` (absolute), else `%SystemRoot%\System32\cmd.exe`, else `cmd.exe`; `resolve_spawn` takes a `cmd_exe` parameter. Reason: testable on macOS.
- `resolveSpawn`/`unsafeForCmdShim` refusals now return `BackendError` code `unsafe_for_cmd`.

PtyHost (xterm-headless to vt100, node-pty to portable-pty):

- `spawn` returns a `Result` and refuses an id that is still live (TS overwrote and orphaned the old process). Reason: no orphans.
- `on_data` and `attach` return `None` for an unknown id (TS returned a no-op unsubscribe). Reason: explicit.
- `on_data` delivers bytes aligned to UTF-8 boundaries, not strings. Reason: Rust strings.
- Exit code is `u32`; a signal kill gives 1 (portable-pty). Reason: library behavior, documented.
- `serialize` replays only the alternate screen when active, and history rows lose their soft-wrap flag. Reason: vt100 does not expose the hidden normal screen.
- `serialize` appends `?1004h`, `?7l` and `4h` when they differ from the defaults. Reason: keep attached terminals in sync with modes vt100 does not replay.
- `dispose` escalates to SIGKILL after 1.5 s (TS only sent SIGHUP). Reason: really kill and reap; needs a tokio runtime with time.
- The exit event waits up to 200 ms for the reader (on Windows always the full 200 ms). Reason: final output lands first; ConPTY EOF only after the pseudoconsole closes.
- `feed` runs the parser and responder but is not broadcast to `on_data` (same as TS `term.write`).
- Unicode widths come from unicode-width 0.2 (Unicode 16), not xterm's Unicode 11. Reason: vt100. Rare characters may differ.
- Resize does not reflow (xterm reflows on column change). Reason: vt100.
- `set_replies(bool)` is replaced by `mute_replies(id) -> Option<ReplyMute>`, a counted guard. Reason: two attached terminals cannot unmute each other.
- A panic in the vt100 parser is caught: the screen is blanked and reading continues. Reason: never freeze the agent on a full PTY buffer.
- `ensureSpawnHelper` has no port. Reason: node-pty specific.
- The reader thread and fd can linger while a grandchild holds the slave (screen freed). Reason: parked, same as Node.

Backend and errors:

- `BackendError` is `{ code: Option<String>, message, request_id: Option<String> }`: it merges TS `BackendError`, `BackendBusyError` and plain `Error` into one type (see Notes for R2). Reason: one error type per Global Constraints, no information lost.
- Git, IO and spawn failures in `hire` are plain errors (no code), as in TS; PtyHost's duplicate-id error is coded `backend_error`.
- `NativeBackend` is generic over `PtyLike`, a smaller trait than TS `Pick<PtyHost, ...>`; TUI-only members are reached through `pty()`. Reason: Rust generics.
- `OfficeBackend` is an `async_trait` trait used as `Arc<dyn OfficeBackend>`. Reason: runtime backend choice in R2; costs a box per call.
- `NativeBackend` needs a tokio runtime with time enabled (`spawn_blocking`, `sleep`, `dispose`). Only `hook` works outside a runtime, via a plain thread for the delayed Enter.
- Transcript containment check is lexical like TS (lowercased on Windows); a symlink inside the projects root can point outside, as in TS.
- `add_repo` uses Node `path.isAbsolute` semantics (on Windows `/x` and `\x` count as absolute).
- Desk id without `::` in `HireSpec::Agent` fails a `debug_assert!`; release returns `not_found` instead of JS `slice(-1 + 2)`. Unreachable after `validate_hire`.
- `HireRequest.desk_id` is `Option<Option<String>>` so `null` and absent differ, as in TS.
- Empty prompt mirrors JS truthiness (`Some("")` gets no warning and no queued prompt).
- Registry load is stricter: malformed repo entries are dropped and non-string desk fields ignored (TS keeps garbage verbatim). Unknown fields survive a round trip (flattened).
- Registry and award saves use `<file>.<pid>[.<n>].tmp` (TS `.tmp`) with a Windows rename retry. Reason: concurrent processes.
- `os.homedir` is approximated by absolute HOME or USERPROFILE, else the OS home, else the temp dir.
- Unix `find_command` checks any exec mode bit, not `access(X_OK)`. Reason: no libc call for it.
- Windows path helpers (isAbsolute, extname, join) are hand-rolled so they are testable on macOS.

Git:

- Error text approximates Node's `Command failed: git -C cwd args\n<stderr>`, plus `timed out` and `stdout maxBuffer length exceeded` (names the stream).
- On timeout or overflow the child is killed and partial stdout is kept (capped at the max for overflow); readers are not joined after a kill because a grandchild may hold the pipes.
- `normalize_path` is component based: drops trailing separators (Node keeps them), no UNC edge cases.
- `worktree_dest` sanitizes per UTF-16 unit (an emoji becomes `__`), like JS.
- Diff truncation counts UTF-16 units like TS; a cut inside a surrogate pair keeps one unit fewer (a lone surrogate is unrepresentable).

Transcripts, stats, conversation:

- Cache identity is by path and resets only when `size < offset`, exactly like TS (blind to a same-size replacement). Per-path locking; the API is sync.
- A lone surrogate escape (`\ud800`) is replaced by U+FFFD where serde_json would reject it; the line is still parsed.
- Dates: RFC 3339, offset-less date-time (local) and date-only (UTC) are understood; other JS `Date` formats count as not-today. A DST gap falls back to the nearest valid local time.
- Task-notification status uses ASCII-lowercase substring checks instead of `/i` regexes.
- `QuestionState.answers` is a `BTreeMap`, so JSON keys come out sorted (JS: insertion order). Value-equal; the web uses keyed lookup.
- `messages` and `images` are `Arc<Vec<_>>` (copy-on-write) so polls do not deep-copy.
- `fileId` is pinned to a placeholder in goldens (it hashes the absolute path); the hash formula is tested separately.
- "Today" for stats is taken from the zone of the `now` the caller passes.

Model and helpers:

- Timestamps are `i64` ms; `since`, `lastActivityAt` and `resetsAt` accept a JSON float and truncate (lenient deserializer for Orca values). Only `usedPercent` is `f64`; goldens compare integral floats as equal to integers.
- `localeCompare` is a hand port of the ICU primary order (punctuation, digits, letters, accents via NFD, lowercase first), verified for ASCII, accented Latin and Hangul; other scripts sort by code point.
- JS `slice` on UTF-16 that would split a surrogate pair drops the whole char (`jsstr::slice_utf16`).
- Permission regex in hooks is ASCII-case-insensitive (`(?i-u)`), matching JS `/i` without `u`.
- `normalize_pr` yields `None` for float or huge digit strings that `Number()` would mangle.

Awards, uploads, commands, answers:

- `AwardBook` keeps raw JSON entries (unknown fields and junk hall entries survive a save); the hall is cut to 90 before filtering, as in TS.
- `IMAGE_TYPES` lookup is exact (TS reads a plain object, so `constructor` would slip through).
- `Buffer.from(base64)` is a hand-written lenient decoder (both alphabets, strays skipped, stops at `=`), checked against Node in a golden.
- `clean_old_uploads` skips directories and ignores delete errors (TS would reject the whole promise).
- `parse_images` validates each image in TS order (count, shape, media type, decoded size) and stops at the first failure.
- `commands`: directory entries are sorted by name (TS uses readdir order), so same-name collisions inside a folder may differ; `installed_plugins.json` keeps file key order; `CommandCatalog` does not share an in-flight scan between concurrent misses.
- `validate_choices` takes the raw JSON and returns the parsed choices (`Vec<Vec<usize>>`); `answer_questions` takes only validated input. A choice outside 1-9 or missing returns an error instead of pressing a garbage key.
- `AnswerRequest.choices` is a `serde_json::Value` (wire shape unchanged) so malformed input is caught by `validate_choices`, not by deserialization.
- The upload-folder ownership check message is unit-untested (needs a second user).

Parked (known, accepted): localeCompare for symbols and non-Latin scripts, float timestamps truncated to ms, `win32_join` without normalize, `win32_has_ext` with a trailing separator, git error text approximation, an alias grandchild orphaned after a git timeout (same as Node), `ureq` pulls the `url`/ICU crates, a panic on `thread::spawn` in the relay, ConPTY exit about 200 ms late, signal-kill exit code 1.

## Notes for R2

The server (axum or similar) must do the following. Each item is checked against the code.

- **Runtime.** Use a tokio runtime with the `time` feature on. `NativeBackend` and `PtyHost::dispose` use `spawn_blocking` and `tokio::time`.
- **`spawn_blocking` for sync IO.** These APIs are sync and block on disk or processes: `Registry` (`load`, `add_repo`, `set_meta`), git (`SystemGit`, `list_worktrees`, `change_summary`, `file_diff`), `transcript::read_transcript` (holds a per-path lock across the read), `uploads::save_images` / `clean_old_uploads` / `read_local_image`, `CommandCatalog::get`, `AwardBook` (`load`, `update`, `save`) and `org::load_org` / `save_org`. `NativeBackend` already wraps its own git and registry calls.
- **`BackendError` to HTTP** (documented on the type in `src/backend/types.rs`):
  - busy (`is_busy()`, code `agent_busy`) gives 409 with `code` and `requestId`;
  - plain (`code` is `None`) gives 502 with no `code` key;
  - `/api/hire` answers any error with 400 and the message;
  - coded (`new` / `with_code`) gives 400 with `error` and `code`.
  - The answer driver's failures are `BackendError::plain` with a Korean message; the route answers 409 with that `message`. `UploadError::Rejected` gives 400 and `Io` gives 502.
- **Raw body values.** Call `uploads::parse_images(&Value)` on the raw `images` field and `answer::validate_choices(&questions, &Value)` on the raw `choices` field before using them. `SendRequest.images` stays typed and `AnswerRequest.choices` is a `Value` for this reason. The answer route builds `BackendAnswerIO { backend, handle }` and calls `answer_questions`; it answers `{"ok":true}` on success.
- **`/term` and `PtyHost::attach`.** `attach(id, f)` serializes the screen and registers the subscriber atomically under the screen lock, so each chunk is either in the snapshot or delivered to `f`, never both and never neither. `f` may run before `attach` returns, so queue what it receives and send the snapshot first. It returns `None` for an unknown id. The returned `Subscription` is `#[must_use]`; dropping it unsubscribes. While a real terminal is attached, hold `mute_replies(id)` (a `ReplyMute` guard; replies resume when every guard is dropped) so the agent's DA/DSR queries are answered by the terminal, not twice.
- **Hook relay.** The server must start the process with `OFFICE_DESKS_HOOK_URL` set and the binary must dispatch `hook-relay` to `hook_relay::run()` and exit with its code.
- **Orca and the rest.** `OfficeBackend` is an `async_trait`; hold it as `Arc<dyn OfficeBackend>`. The Orca backend (R3) must produce `BackendError::busy(request_id)` for `agent_busy`; the native backend never raises it.
