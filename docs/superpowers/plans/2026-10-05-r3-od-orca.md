# R3: od-orca (the Orca and demo backends in Rust) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the Orca backend (CLI runner, `terminal_not_writable`, the busy/retry map, sessions, usage, search) and the demo backend to a new crate `od-orca`, and make the `office-desks` binary pick native, Orca or demo exactly like the Node bridge, including the `orca status` probe. Orca users and `--demo` then run on Rust.

**Architecture:**
- **A separate crate, not an od-core module.** `crates/od-orca` depends on `od-core` only. Reasons:
  - Orca is optional on the roadmap (native backend first, Orca on top when present). The native core, which R4 embeds in the app, should not carry an Orca CLI runner, the demo fixtures or tokio's `process` feature.
  - The Orca code has its own process-level test binary: a fake `orca` executable, in the same self-dispatch style as R2's fake agent. It lives in its own crate.
  - od-core already holds what Orca shares with native: the Orca row types and `to_snapshot` in `state_mapper`, and `resolve_windows_command` and `unsafe_for_cmd_shim`. od-orca reuses them.
- **Backend selection lives in od-server.** It ports `backend/index.ts` `createBackend` as `od_server::create_backend`, so R4's app reuses the same selection. od-server gains a normal dependency on od-orca. There is no cycle: od-orca does not depend on od-server.
- **The runner is a trait.** `OrcaRunner::run(&self, args: &[String]) -> Result<Value, BackendError>` is the TS `OrcaRunner`. Three things implement it:
  - `OrcaCli`, the real process runner: `std::process::Command` (argv only), converted to `tokio::process::Command`, with a timeout;
  - a fake runner, in unit tests;
  - `DemoRunner`, the fake office.

  `OrcaBackend` builds every argv itself. `DemoBackend` wraps an `OrcaBackend` over `DemoRunner` and overrides only name, capabilities, messages and `snapshot`, as `DemoBackend extends OrcaBackend` does in TS.
- **Sessions.** `SessionResolver` ports `sessionResolver.ts`. Each resolve runs in its own spawned task, and concurrent callers for the same agent share it through a `futures_util::future::Shared`. A guard removes the in-flight entry even on panic. So a slow `orca search` can never pile up more than one process per agent, and a dropped `/api/conversation` request cannot stall it. Every CLI call is bounded by the runner's 15 s timeout, and a whole resolve by 30 s.
- **R3 modifies Node.** R2's rule "Node stays untouched" does not hold here. Recording a deterministic demo contract needs a fixed clock in `bridge/src/demo.ts` (env `OFFICE_DESKS_DEMO_EPOCH`, Task 7). The recorder also gets a demo mode, and there is a read-only Node smoke script (Task 8). Nothing else in `bridge/src` changes.
- **od-core housekeeping first.** Task 1 folds the R3 backlog from od-core PARITY into od-core, with no behavior change:
  - one `nodepath` module for the Node path helpers;
  - one `util::lock` and one `util::epoch_ms`;
  - `jsval::string` / `number_to_string`, moved from od-server;
  - `jsstr::slice_utf16`, made public.

## Global Constraints

- **Platforms.** macOS and Windows are first-class. Every test runs on both in the CI `rust` job: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. There are three exceptions:
  - the recorder, which is a macOS dev tool;
  - the Windows-only `.cmd` shim trials, which run only on Windows CI;
  - the read-only Orca smoke test, which runs by hand on the user's Mac, and only with permission.
- **No shell.** Every process gets an argv array (`std::process::Command`, `tokio::process::Command`, `child_process.spawn(file, args)` without `shell: true`). Never `sh -c` and never a `cmd /c` written by us. There is one exception, as in TS `createOrcaRunner`: when the Orca CLI resolves to a `.cmd`/`.bat` shim on Windows, it is spawned by passing that path to `std::process::Command`, and std builds the `cmd.exe` line itself with its own batch escaping. Before that, every argument is checked with `od_core::native::pty_host::unsafe_for_cmd_shim` and refused (TS rule). The fake-orca tests write one `.cmd` file as a fixture.
- **Ports.** Never use port 4317 in any test, script or E2E. Tests bind `127.0.0.1:0`. Scripts pick a free port the same way, close it, and assert it is not 4317.
- **Scratch only.** Never read or write the user's `~/.office-desks`, `~/.claude` or `~/.codex`, and never touch the user's repos.
  - Tests, the recorder and the bin tests use scratch `OFFICE_DESKS_HOME`, `HOME`/`USERPROFILE`, `CLAUDE_CONFIG_DIR`, `TMPDIR`/`TMP`/`TEMP` and git config, as in R2.
  - Demo files go under the scratch temp dir (`<tmp>/office-desks-demo`).
  - Every `ServerConfig` in a test overrides `upload_dir`, `commands_home`, `org_file`, `awards_file` and `assets`.
- **Never touch Orca.** No test, script or CI step may run the user's real `orca` CLI or signal an Orca process. The one exception is Task 8's read-only smoke test, and only after the user says yes.
  - Every bin test sets `ORCA_CLI_COMMAND` to a path that does not exist inside its scratch dir. With PATH cleared, spawn would otherwise fall back to a default search path.
  - Every Node recording sets `OFFICE_DESKS_BACKEND` explicitly, so the bridge never probes.
  - Unit tests use the fake runner. Process tests use the fake `orca` copied into a scratch dir and called by absolute path.
- **Process discipline.** Kill only PIDs you started. The runner kills only its own `orca` child, on timeout or drop. Never `pkill`, `killall`, or kill by name or pattern. On Windows, a `.cmd` shim's grandchild can outlive a timeout kill, as in Node; never hunt for it.
- **Wire compatibility.**
  - JSON field names follow `model.ts`.
  - Error codes and messages are exactly TS's.
  - Every `BackendError` the Orca and demo backends produce carries a code: `BackendError::with_code` or `BackendError::new` (code `backend_error`, the TS default), or `BackendError::busy`. `BackendError::plain` never appears in `crates/od-orca/src` (a test enforces this, Task 4).
- **Messages.** Korean and English user-facing strings are copied verbatim from the TS source. Here they are, so nobody retypes them:
  - `NOT_WRITABLE`: `이 에이전트 터미널에 입력할 수 없어요 (터미널이 끊겼거나 Orca 화면에 붙어 있지 않음). Orca에서 터미널을 다시 연 뒤 보내 주세요` (code `terminal_not_writable`);
  - Orca `noSession` (also the demo's): `Orca 세션 검색에서 이 에이전트의 대화 기록을 찾지 못했습니다. (Orca Settings → Agent Session History가 켜져 있어야 합니다)`;
  - Orca `hireDisabled`: `이 백엔드에서는 새 작업을 만들 수 없어요`; demo `hireDisabled`: `데모 모드에서는 만들 수 없어요`;
  - retry of an unknown id: `다시 보낼 메시지를 찾지 못했습니다. 새로 보내주세요` (code `not_found`);
  - `addRepo`: `Orca에서는 Orca 앱에서 프로젝트를 추가해 주세요` (code `unsupported`); `stopAgent` and `removeWorktree`: `이 백엔드에서는 할 수 없어요` (code `unsupported`);
  - hire warning: `에이전트는 띄웠지만 준비가 늦어 첫 지시는 보내지 못했어요. 패널에서 보내 주세요`;
  - `.cmd` refusal: `Windows의 orca.cmd로는 줄바꿈이나 " % & | < > ^ ! 문자를 안전하게 보낼 수 없습니다. ORCA_CLI_COMMAND에 orca.exe 경로를 지정해 주세요` (code `unsafe_for_cmd`);
  - runner: `Orca CLI "<command>" not found on PATH` (`not_found`), `orca <args[0]> <args[1] or empty> timed out` (`timeout`; note the two spaces when there is no second argument), `orca exited with <code or null>`;
  - usage labels: `5시간`, `주간`, `월간`, `Fable 주간`, `<Name> 주간`, `<Name> 월간` and `<n>시간`;
  - startup line: `[office-desks] bridge on http://127.0.0.1:<port> (<label>)` with label `DEMO data`, `orca backend, orca cli: <command>` or `native backend`.
- **Blocking IO.** Sync od-core APIs that touch disk run under `tokio::task::spawn_blocking` (`read_transcript`, demo file writes inside async code). `DemoBackend::new` and `server_files` are sync and run before the server starts.
- **Commits.** Each task ends with at least one commit. The message is a subject, a blank line, then exactly:

  Write the message to a file in the scratchpad and run `git commit -F <file>`. Pushing the `Jang-seungminn/r3-orca` branch is allowed; never push another branch.

## Review Focus

1. **A missing, stopped or hung `orca`.** A person who starts `office-desks --backend orca` without Orca running expects the office to open and show the error text, not to crash. A hung `orca` must never leave a pile of processes behind.
   - One CLI call is killed after 15 s (3 s for the probe).
   - Session searches run at most one per agent.
   - A whole resolve gives up after 30 s.

   Pinned by:
   - Task 2: the fake-orca timeout trial checks that the child's PID is gone;
   - Task 3: the dedupe test (five concurrent callers make one search) and the paused-clock timeout test;
   - Task 6: a bin test with a missing `ORCA_CLI_COMMAND` shows `Orca CLI "<path>" not found on PATH` in `snapshot.error`.
2. **Windows `.cmd` installs and odd text.** A Windows user whose Orca CLI is an npm-style `orca.cmd` expects these to work:
   - Korean text, spaces, parentheses and `--text=--help` arrive byte for byte;
   - a multi-line prompt is sent space-joined;
   - text with `%`, `&` or `"` is refused with the Korean `unsafe_for_cmd` message, without running anything.

   Pinned by Task 2's Windows-only shim trials (the round trip through a real `.cmd` in a folder with a space in its name, and the refusal before spawn) and by Task 4's newline-join test.
3. **A prompt sent while the agent shows a dialog.** Orca refuses it with a request id.
   - The person sees 409 `agent_busy` and presses "다시 보내기".
   - The retry re-sends the original text, even after a second refusal.
   - After 10 minutes the id is forgotten and the retry answers 404.

   Pinned by Task 4's port of the four blocked-prompt tests, plus a test that a re-blocked retry keeps the original argv and not the retry argv.
4. **Orca JSON drift.** A newer or older Orca may send things TS would trip over:
   - a `worktrees` value that is not an array;
   - a `tail` with non-string rows;
   - `hits: null`;
   - floats for timestamps;
   - a result that is not an object.

   The person expects a degraded office, not a 502 on every poll. Pinned by Task 4's "lenient shapes" test and Task 2's `parse_output` vectors.
5. **Session lookup with real-world text.** These must find the right transcript:
   - prompts in Korean or with emoji (80 and 40 UTF-16 unit cuts that never split a surrogate pair);
   - a cwd with a trailing slash;
   - on Windows, a cwd that differs only in case or separators.

   Pinned by Task 1's `same_path` vectors and Task 3's `search_key` and verifier tests.

- **`SessionResolver`.**
  - **State.**

    1. Lock `inflight`. If an entry for `agent.id` exists, clone its `Shared`, unlock, and await it.

Its `Drop` removes the in-flight entry only if the generation still matches, so a panic cannot wedge an agent. The task runs `tokio::time::timeout(RESOLVE_TIMEOUT, me.resolve_now(...))`.     4. Wrap the `JoinHandle` as `async move { handle.await.unwrap_or_else(|e| Err(BackendError::new(format!("session search failed: {e}")))) }.boxed().shared()`.

       - `source.presence` is not the string `missing`;
       - `source.filePath` is a non-empty string;

## Open judgment calls

1. **`od-orca` is a crate, not a module in od-core.** The reasons are in Architecture.
2. **`create_backend` lives in od-server**, not in the binary, so R4's app reuses it. od-server now depends on od-orca.
3. **The 60 s `terminal wait` runs under the 15 s runner timeout.** It is kept as in TS and parked in PARITY. The alternative is a per-call timeout for `terminal wait`.
4. **Lenient handling where TS would throw.** Non-object results and non-array lists degrade to empty; TS gives a 502 or an uncaught error.
5. **New bounds.** stdin is null, there is a 32 MiB output cap, and a 30 s overall session resolve timeout.
6. **The probe runs after the bind** (Node probes before listening).
7. **The demo contract skips `awards`**, which is TZ and today dependent, and the demo clock hook is added to Node.
8. **No snapshot sharing inside the backend.** The poller is its only caller.
