# R2: od-server (the HTTP/WS API in Rust) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Rust crate `od-server` (axum + tokio) and a binary `office-desks`. Together they serve the complete HTTP/WS API of `bridge/src/server.ts` on top of `od_core::backend::NativeBackend`, plus the new `/term` WebSocket, so the unchanged web office runs against Rust.

**Architecture:**
- **Shape of the server.** One axum app with a single fallback handler. That handler ports the `if` chain of `server.ts` in order: security guard, then `/hook/*`, then `/api/*`, then static files. It does not use axum's typed router: the TS chain has its own 405/415/404 rules and route order that a router would change.
- **State.** One `AppState` holds:
  - the backend, as `Arc<dyn OfficeBackend>`;
  - the poller;
  - a WS broadcast hub;
  - the org chart, the award book and the usage value;
  - the slash-command catalog;
  - the set of terminals being answered;
  - the git change cache.

  R3 plugs the Orca and demo backends in through the same `Arc<dyn OfficeBackend>`. Every capability branch in `server.ts` stays in the Rust code and is tested with a `FakeBackend`.
- **Contract harness.** The harness is built early (Task 2), and every route task turns its part on:
  - A shared `steps.json` lists requests.
  - A Node recorder drives the real bridge (native backend, scratch homes, a fake agent, a random port) and writes response fixtures.
  - A Rust runner replays the same steps against od-server and compares status, an allowlist of headers, and the normalized body.
- **Bin crate.** `crates/office-desks` dispatches `office-desks hook-relay` to `od_core::native::hook_relay::run` before any runtime starts. Otherwise it runs the server: flags from `bin/office-desks.mjs`, no TUI yet.
- **Node stays untouched.** The Node bridge is not modified. R2 adds only the recorder script and its npm script.

**Tech Stack:**
- Rust 1.94, edition 2021 (workspace `rust-version = "1.85"`).
- Server crates:
  - axum 0.8 with the `ws` feature;
  - tokio 1 with `rt-multi-thread`, `macros`, `net`, `time`, `sync`, `signal` and `fs`;
  - serde and serde_json 1, url 2, percent-encoding 2, getrandom 0.4 (the same as od-core);
  - chrono (as od-core);
  - rust-embed 8 (needs the missing-folder option, see Task 1);
  - tower-http (`CatchPanicLayer`, Task 1);
  - futures-util 0.3.
- Dev crates:
  - tempfile 3;
  - hyper 1, hyper-util (legacy client, http1) and http-body-util, for requests whose headers are sent exactly as given (including `Host`);
  - tokio-tungstenite, for WS clients;
  - libtest-mimic, for the `harness = false` native test binary;
  - sha2, async-trait;
  - libc (unix) and windows-sys (Windows), for the fake agent's raw mode;
  - libc (unix) is also a dev-dependency of `crates/office-desks`, for the SIGINT test (Task 10).
- Recorder: a `tsx` script using `node:http`, `node:crypto` and the `ws` package the bridge already depends on.

**Spec:** `docs/superpowers/specs/2026-10-05-desktop-app-design.md` (milestone R2 plus "Cross-cutting rules"). The behavioral spec is `bridge/src/server.ts`, `security.ts`, `poller.ts`, `backend/index.ts` and `bin/office-desks.mjs`. `crates/od-core/PARITY.md` ("Notes for R2") is binding: its error table, request-body rules, `/term` notes and hook-relay notes are requirements of this plan. ## Global Constraints

- **Platforms.** macOS and Windows are first-class. Every test runs on both in the CI `rust` job: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. The one exception is the recorder (Task 2), which is a macOS dev tool; Windows only replays the committed fixtures.
- **No shell.** Never use a shell. Every process gets an argv array: `std::process::Command`, `tokio::process::Command`, `child_process.spawn(file, args)` without `shell: true`. No `sh -c`, no `cmd /c` written by us. (PtyHost's own `.cmd` shim rule from R1 is the only exception.)
- **Ports.** Never use port 4317 in any test, script or E2E. Tests bind `127.0.0.1:0`. Scripts pick a free port by binding `127.0.0.1:0`, reading the port and closing the socket, then assert it is not 4317.
- **Bind address.** The server binds `127.0.0.1` only. There is no option to change that.
- **Scratch only.** Never read or write the user's `~/.office-desks`, `~/.claude` or `~/.codex`, never touch Orca, and never touch the user's repos. Tests, the recorder and the E2E use:
  - scratch `OFFICE_DESKS_HOME`, `HOME`/`USERPROFILE`, `CLAUDE_CONFIG_DIR` and `TMPDIR`/`TMP`/`TEMP`;
  - a scratch git config (`GIT_CONFIG_GLOBAL=<scratch>/gitconfig`, `GIT_CONFIG_NOSYSTEM=1`);
  - scratch git repos.

  `OFFICE_DESKS_BACKEND=native` is always set explicitly. Without it the Node bridge probes Orca with `orca status`.

  In Rust tests, never call `od_core::uploads::upload_dir()`, `CommandCatalog::new()` or the default `org_file`/`awards_file`. Pass scratch paths through `ServerConfig`.

  The only exception is Task 12's fallback for real Claude's login, and only with the user's explicit approval.
- **Process discipline.** Whatever starts a process records its PID and stops only that PID (and agents it can prove it started). Never `pkill`, `killall` or kill by name or pattern. Rust tests that spawn agents hold a drop guard that kills their own fake-agent PIDs on panic.
- **Wire compatibility.**
  - JSON field names follow `model.ts`.
  - Status codes and messages are identical to `server.ts`; copy the Korean messages verbatim from the TS source.
  - JSON responses carry `content-type: application/json` exactly (no charset).
  - Request bodies are parsed as `serde_json::Value` and checked by hand, never with axum's `Json<T>` (PARITY.md, "Request bodies").
- **Blocking IO.** Sync od-core APIs that touch disk or processes run under `tokio::task::spawn_blocking`. The full list is in PARITY.md, "Notes for R2".
- **Commits.** Each task ends with one commit (more are fine). The message is a subject, a blank line, then exactly:

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_013wdfUqZP1py6R116oZnY8V
  ```

  Write the message to a file and use `git commit -F <file>`. Do not push.
- **Test assets.** Every Rust test passes `assets: Arc::new(MemAssets(..))`, empty unless the test needs files. In debug builds rust-embed reads `web/dist` from disk, so a developer's built web UI must never change a test result.
- **Messages.** Korean user-facing messages are copied verbatim from the TS source (or from PARITY.md where it quotes them). New messages that only R2 introduces (`/term`, the bin) are listed in this plan with their exact text.

## Review Focus

1. **JS coercion in request fields.** A person who sends `comment: null` expects to see `"null"` saved, exactly as the Node bridge does. A person who opens `?after=abc` expects the conversation from the start. The rules:
   - `String(x)` for `comment`;
   - JS `Number(x)` for `after` and `i`. Missing becomes `Number(null)`, which is 0; `''` is 0; `' 2 '` is 2; `'0x10'` is 16; `'abc'` is NaN;
   - JS truthiness for `force`;
   - the JS `\s` set, and UTF-16 length, for comment collapsing and the 200 and 1000 limits.

   Pinned by unit tests in Task 1 (`js.rs`) and contract steps in Tasks 4, 6 and 7.
2. **The office stays live.** A browser that connects to an idle server sees a refresh at once, not after up to 10 s. Every POST that changes something shows in the office within one poll. A slow WS client that lags the broadcast gets the current state re-sent instead of silently missing an `org` or `awards` message. Pinned in Task 3.
3. **`/term` attach is gap-free, and the mute is released.**
   - No output byte is lost or doubled between the snapshot and the stream.
   - A client that vanishes without a close frame still releases its `ReplyMute`, so the agent's DA/DSR queries get answered again.
   - A client too slow to keep up is closed (1013) instead of buffering without bound.

   Pinned in Task 9.
4. **Windows paths.**
   - Desk ids and paths use forward slashes.
   - `path.isAbsolute` follows Node's win32 rules for `/api/local-image`. `C:\x` and `\x` are absolute; `C:x` is not.
   - Upload names are checked by the `[\w-]+\.(png|jpg|gif|webp)` rule.
   - Static paths with `..\` or `%5C..` never leave the asset root.

   Pinned in Tasks 7 and 10. The contract replay runs on the Windows CI runner, and on Windows the runner also asserts that no snapshot desk `id`, `path` or `repoId` it sees contains `\` (enforced by the harness since Task 2's fix round 1).
5. **Shutdown and startup failures.**
   - Ctrl+C or SIGTERM stops every agent the server started, then exits 0. A second signal does nothing.
   - A port already in use prints `[office-desks] <error>` and exits 1, without leaving a half-started backend.

   Pinned in Task 10 on unix. The Windows bin test is only a smoke test (`child.kill()` is TerminateProcess); that gap is recorded in od-server PARITY (Task 11).

## Public API of od-server (all tasks code against this)

```rust
pub type EnvMap = od_core::native::env::EnvMap;

pub struct ServerConfig {
    pub tui_active: bool,              // OFFICE_DESKS_TUI: the poller never idles (R5)
    pub poll_interval: Duration,       // 1500 ms
    pub idle_interval: Duration,       // 10_000 ms (poller.ts IDLE_INTERVAL_MS)
    pub usage_interval: Duration,      // 60_000 ms
    pub hire_recheck: Duration,        // 2500 ms (HIRE_RECHECK_MS)
    pub upload_dir: PathBuf,
    pub commands_home: PathBuf,        // home CommandCatalog scans (~/.claude, ~/.codex)
    pub org_file: PathBuf,
    pub awards_file: PathBuf,
    pub default_org: Option<OrgChart>, // R3 demo: used when the loaded org has no departments
    pub assets: Arc<dyn Assets>,
    pub ws_buffer: usize,              // hub broadcast capacity, 256
    pub term_buffer: usize,            // /term outbound queue length per client, 1024 chunks (Task 9; plus a fixed 8 MiB byte budget)
}
impl ServerConfig {
    /// Real defaults: upload_dir(), od_core::home::os_home() (made pub in Task 1), org_file(None, env), awards_file(None, env), WebDist.
    /// upload_dir()/org_file() only compute paths and do no IO, so tests may call this and then override the paths.
    pub fn from_env(env: &EnvMap) -> Self;
}

pub struct Bound { /* tokio TcpListener on 127.0.0.1 */ pub port: u16 }
/// Bind 127.0.0.1:<port> (0 = any free port). Error text is the io::Error's Display.
pub async fn bind(port: u16) -> std::io::Result<Bound>;

/// `http://127.0.0.1:<port>/hook/<encodeURIComponent(agentId)>?token=<token>` (backend/index.ts).
pub fn hook_url(port: u16) -> impl Fn(&str, &str) -> String + Send + Sync + 'static;

/// Port of createNativeBackend: office_home(env), Registry(<home>/state.json) loaded on the blocking
/// pool, PtyHost::new(), hook_url(port), deps.env = Some(env.clone()).
pub async fn native_backend(env: &EnvMap, port: u16) -> od_core::backend::NativeBackend;

/// Start the poller, usage loop, upload cleanup and the HTTP server. Returns at once.
pub async fn serve(bound: Bound, backend: Arc<dyn OfficeBackend>, cfg: ServerConfig) -> ServerHandle;

pub struct ServerHandle { pub port: u16, pub term_token: String, /* … */ }
impl ServerHandle {
    pub fn poller(&self) -> &Arc<Poller>;   // added in Task 3, with Poller
    /// Stop accepting, stop the poller and usage loop, then `backend.dispose().await`. Idempotent.
    pub async fn shutdown(&self);
    /// Resolves when the accept loop has ended (after shutdown).
    pub async fn closed(&self);
}

pub trait Assets: Send + Sync { fn get(&self, path: &str) -> Option<Cow<'static, [u8]>>; }
pub struct WebDist;          // rust-embed over ../../web/dist
pub struct MemAssets(pub HashMap<String, Vec<u8>>); // tests
```

Details:
- **Guard.** `is_allowed_request` ports `security.ts` exactly:
  - `Host` must match `^(\[[^\]]+\]|[^:]+)(?::(\d+))?$`, with a hostname (lowercased) in `localhost`, `127.0.0.1` or `[::1]` and a port in `allowed_ports`.
  - `Sec-Fetch-Site`, if present, must be `same-origin` or `none`.
  - `Sec-Fetch-Dest` must not be `iframe`, `frame`, `embed` or `object`.
  - `Origin`, if present, must parse as a URL with scheme `http:` and a host that passes the same local check. Note that the literal string `null` fails.
  - The allowed ports are `[bound port, 5173]`.
- **Headers.** `apply_headers` sets the five headers from `setSecurityHeaders`, with the CSP joined by `"; "` in the TS order. It runs on **every** response: 403s, `/hook` 204/404/400 and static files included. Install it as a middleware that wraps the dispatcher.
- **Dispatcher order** (`app.rs`, port of the `createServer` callback):
  1. Guard: if it fails, 403 `{"error":"forbidden origin"}`.
  2. `RequestUrl::parse` of the raw request-target: if it fails, 400 `{"error": <message>}`.
  3. POST with a pathname starting `/hook/`: the hook handler (Task 5; until then 404 with no body).
  4. A pathname starting `/api/`: `routes::dispatch`.
  5. Otherwise: static (Task 10).

  WS upgrades are dispatched before this chain (Tasks 3 and 9).
- **Catch-all.** Wrap with tower-http's `CatchPanicLayer` (add `tower-http`), mapping a panic to 502 `{"error":"internal error"}`. Put the layer **inside** the security-header middleware, so a panic's 502 still carries the five headers.
- **Assets.** `src/assets.rs` holds:
  - the `Assets` trait and `MemAssets` as in the public API;
  - `WebDist`, `#[derive(RustEmbed)] #[folder = "../../web/dist"]` with rust-embed 8 pinned and `#[allow_missing = true]`. Confirm the option exists in the pinned version by building with `web/dist` absent: the CI `rust` job has no `web/dist`, so the crate must compile without it;
  - `build.rs`, which prints `cargo:rerun-if-changed=../../web/dist`.

  `ServerConfig::from_env(env)` sets `upload_dir` to `od_core::uploads::upload_dir()`, `commands_home` to `od_core::home::os_home()` (TS `os.homedir()`, which reads the process `HOME`; it ignores the env map), `org_file` and `awards_file` to the od-core defaults for `env`, `assets` to `Arc::new(WebDist)`, `term_buffer` to 1024, and the intervals to the values in the public API. In T1 the static arm answers the no-dist text whenever `assets.get("index.html")` is `None`, and 404 otherwise, until Task 10.
- **URLs.** `RequestUrl::parse` joins the raw target onto `http://127.0.0.1:<port>` with `url::Url::join` (WHATWG, like Node `new URL(req.url, base)`):
  - dot segments are removed;
  - `+` becomes a space in query values;
  - the pathname stays percent-encoded, as in Node.
- **JS helpers.** `js::number` implements `Number(string)` (the `js` module re-exports od-core's `jsstr` helpers, see the Interfaces):
  - trim the JS `\s` set;
  - `''` is 0;
  - `0x`/`0o`/`0b` prefixes are allowed;
  - `Infinity` with an optional sign is allowed;
  - otherwise use the decimal literal grammar, and anything else is NaN.

  `number_of_param(None)` is 0 (`Number(null)`).
- **`js::string`** implements `String(value)`:
  - `null` becomes `"null"` and booleans become `"true"`/`"false"`;
  - numbers use the JS number-to-string rules: integers without `.0`, and exponent form at 1e21 and above, as in `1e+21`;
  - a string is itself;
  - an array is its elements' `String` joined by `,`, with null elements empty;
  - an object is `"[object Object]"`.
- **Whitespace.** od-core's `jsstr::is_js_space` already covers the JS `\s` set (`\t \n \v \f \r`, the space, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000 and U+FEFF). Do not write a second table; `js.rs` only re-exports it.
- **URI helpers.**
  - `decode_uri_component` is strict: a malformed `%`, or bytes that are not valid UTF-8, give `None`.
  - `encode_uri_component` leaves `A–Z a–z 0–9 - _ . ! ~ * ' ( )` and encodes everything else as UTF-8 `%XX` (uppercase).
- **Node path helpers.** `node_basename` and `node_is_absolute` follow Node's rules for the OS the server runs on.
  - **Basename:** trailing separators are dropped. On Windows, `\` is a separator and a drive prefix is stripped.
  - **Absolute:** on unix, a leading `/`. On Windows, call od-core's `native::env::win32_is_absolute` (made pub above): a leading `\` or `/`, or a drive letter followed by `:` and a separator.
  - Write `node_basename` fresh: od-core's private `basename` does not strip a drive prefix.
- **`read_json`** collects the body stream and counts bytes.
  - Over `cap`: `ApiError::BadRequest("요청이 너무 큽니다")`.
  - It then parses with `serde_json::from_slice`. A failure is `ApiError::BadRequest(<serde message>)`. This is a deliberate difference: V8's text can't be reproduced, and contract steps compare status only.
  - Disable axum's `DefaultBodyLimit`.
- **`ApiError`** variants mirror the catch-all table in PARITY.md:
  - `BadRequest(String)`: 400 `{error}`;
  - `Backend(BackendError)`: 409 `{error, code}` when the code is `terminal_not_writable`, else 502 `{error}` plus `code` only when the error has one;
  - `Upload(UploadError)`: `Rejected` is 400 and `Io` is 502;
  - `NullBody(&'static str)`: 502 `{"error":"Cannot read properties of null (reading '<field>')"}`, V8's exact text for `body.<field>` on `null`;
  - `Internal(String)`: 502 `{error}` with no `code`. `From<io::Error>`, `From<GitError>` and `From<JoinError>` build it from the error's `Display`.

  `ApiError` implements `From<BackendError>`, `From<UploadError>`, `From<io::Error>`, `From<GitError>` and `From<JoinError>`. TS adds Node's `code` (e.g. `ENOENT`) to fs errors; Rust does not. Task 11 lists that difference.

**The fake agent.** `tests/native/main.rs` starts by checking `std::env::current_exe()`. If its file stem is `claude`, it runs `fake_agent::run()` and exits. Otherwise, before starting any thread, it does two things:
- sets the process env `HOME`, `USERPROFILE`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM=1`, `TMPDIR`, `TMP` and `TEMP` to a fresh per-process scratch root (`std::env::set_var` is safe in edition 2021, and the process is still single-threaded). These process-wide values are shared by every trial and are a safety net only; each trial passes its own explicit env map to the backend;
- hands the trials to `libtest_mimic::run`. Trials run in parallel, so **each trial gets its own sub-root** `<process root>/<trial name>` with its own setup, `<sub-root>/bin/claude`, `OD_FAKE_AGENT_OUT=<sub-root>/out` (so its own `agents.jsonl`) and its own `PidGuard`. A trial never reads another trial's `agents.jsonl`, and a PidGuard never holds another trial's PID. The `ROOT` template variable is the trial's sub-root.

`fake_agent::run()` does exactly this:
1. Switch stdin to raw mode, the same way as R1's `tests/pty_host.rs` `mod raw`: `cfmakeraw` on unix, and `SetConsoleMode(stdin, ENABLE_VIRTUAL_TERMINAL_INPUT)` on Windows.
2. Append one JSON line to `$OD_FAKE_AGENT_OUT/agents.jsonl`: `{"pid":<u32>,"hookUrl":<OFFICE_DESKS_HOOK_URL or null>,"args":[argv[1..]],"cwd":<cwd>}`.
3. Write `FAKE AGENT READY\r\n`, then a Claude-style composer (`fake_agent::COMPOSER`: a line of 16 `─`, `❯ `, another line of 16 `─`, each ending `\r\n`), and flush. `screen.ts` needs `❯` framed by rules of at least 8 `─` to read `ready`; without it every unforced `/api/send` would be a 409 `menu_open`.
4. Loop on stdin reads (EOF or an error exits 0). Bytes accumulate into a line. On `\r`:
   - strip the bracketed-paste markers `\x1b[200~` and `\x1b[201~` from the line;
   - `query` → write `\x1b[c`;
   - `exit` → write `bye\r\n` and exit with code 3;
   - `menu` → clear the screen and draw an unframed `❯ 1. Yes` (`fake_agent::MENU`, `\x1b[2J\x1b[H❯ 1. Yes\r\n`): a dialog, which `composerState` reads as `menu`;
   - anything else → write `got:<line>\r\n`;
   - then clear the line.

   Every read that starts with `\x1b[?` is echoed as `in:<Rust {:?} of the bytes as lossy UTF-8>\r\n` before the line handling. That makes a headless DA reply visible.

- **Template expansion** happens inside the string values of the parsed JSON body (so Windows backslashes are escaped by the JSON writer), and as plain text in `path`, header values and `bodyRaw`.
- **`steps[]`.** Each step is `{ "name", "group", "kind", … }`. Names are unique; groups are `guard`, `empty`, `manage`, `hook`, `read`, `media` and `input`, in this file order.
  - **`http`:** `method`, `path`, optional `headers`, then one of `body` (any JSON, templated, sent with `content-type: application/json` unless `headers` overrides it), `bodyRaw` (a templated string sent as-is) or `bodyRepeat` (`{ "prefix", "char", "count", "suffix" }`, for the cap tests). Also optional `compare` (`"full"` by default, or `"status"`) and optional `capture` (`{ VAR: [segments] }`).
  - **`waitFor`:** GET `url` (templated; default `/api/snapshot`) every 200 ms until `[segments]` resolves (optionally `equals` a JSON value). "Resolves" means every segment exists and the final value is not JSON `null`; `equals` compares by deep equality. TS and Rust implement exactly this. The timeout is 20 s. It records nothing of the response, and it may `capture`.
  - **`sleep`:** `ms`.
  - **`wsOpen`:** keeps a named socket (`"id"`) to `/ws`, records the first `count` messages, and keeps reading in the background into that socket's queue.
  - **`wsExpect`:** waits ≤ 10 s on the socket `id` for a message whose `type` equals the given one, and records it. It only considers messages that arrived after the step named in `after` **started**: TS broadcasts before it answers, and an org broadcast from startup must not satisfy it.
  - **`wsReject`:** tries `/ws` with the given headers or path and records `{"rejected": true}` when the handshake fails, whatever the status. The fixture stays `{"rejected": true}` because TS destroys the socket. The Rust runner **also** asserts that the handshake response it observed natively is 403. That assertion is guarded by a `const ASSERT_WS_403: bool` in `contract.rs`, which is `false` in this task (no `/ws` arm exists yet, so the request falls to static) and which Task 3 turns on.
  - **`agentInfo`:** finds the `agents.jsonl` line whose `hookUrl` contains `encodeURIComponent(${AGENT})`. It captures `TOKEN` (the query `token`) and `SID` (the argv value after `--session-id`).
  - **`seedTranscript`:** copies `bridge/test/fixtures/claude-rich.jsonl` to `<ROOT>/claude/projects/scratch/${SID}.jsonl`, appending the `append` lines with templates expanded.
  - **`writeFile`:** `{ "path" (templated), "base64" }` writes the decoded bytes to `path`, creating parent folders. It is not recorded (no fixture entry), so the normalizers never see it; the recorder and the Rust runner both implement it.
- **Segments** are object keys, array indexes, `{ "where": { key: value } }`, which picks the first array element whose fields equal those values, or `{ "contains": "text" }`, which picks the first string element containing the text (used to wait for terminal lines).
- **Captures are recorded.** Every step that captures (an `http` or `waitFor` with `capture`, and `agentInfo`) records `"captured": { VAR: shape }`; for a step with no other record the fixture entry is just `{ "captured": … }`. Each value is normalized with the variables known *before* the step plus the step's *other* captures, then id-masked: lowercase UUIDs become `${UUID}`, then every alphanumeric run of 8+ lowercase hex digits becomes `${HEX<n>}` (uppercase is left alone, so a case change shows). The block is not normalized again. This pins the id formats, e.g. `MAIN_DESK` `${REPO_ID}::${ROOT}/repo`, `REPO_ID` `${HEX12}`, `AGENT` `${UUID}:main`, `HANDLE` `pty_${UUID}`, `TOKEN` `${HEX32}`, `SID` `${UUID}`.
- **Header `null`** means "do not send this header" (how "without content-type" is written). Any body kind (`body`, `bodyRaw`, `bodyRepeat`) gets `content-type: application/json` unless `headers` names a content-type.
- **Which variables normalize a record:** those known after the step (its own captures included), so a fixture never depends on a later step.
- **Templates:** `${VAR}` gives the value; `${VAR|uri}` gives its `encodeURIComponent`.
- **Built-in variables:**
  - `ROOT` is the canonical scratch root with `/`; `REPO` is `<ROOT>/repo` in native form;
  - `PORT` and `HOST` (`127.0.0.1:${PORT}`);
  - `NOTREPO` is `<ROOT>/home`, an existing folder that is not a git repo.

  Captured variables add to these.

As built, `steps.json` has **120 steps** (108 fixture entries). `force` is used only where the dialog must be bypassed to reach a later check.

**Fixture format.** One file per group: `fixtures/<group>.json`, holding `{ "<step name>": Recorded, … }`. `Recorded` is:
- `{ "status", "headers": { allowlisted, lowercased }, "body": … }`;
- for WS steps, `{ "messages": [...] }` (`wsExpect` records its one message the same way) or `{ "rejected": true }`;
- plus `"captured": {…}` on capturing steps (see above).

Every group's fixture holds exactly its recording steps: the runner fails a fully run group whose fixture has extra or missing keys. Recording steps are `http`, `wsOpen`, `wsExpect`, `wsReject`, `agentInfo` and anything with `capture`.

The header allowlist is `content-type`, `cache-control`, `x-frame-options`, `x-content-type-options`, `referrer-policy`, `cross-origin-resource-policy` and `content-security-policy`.

The body is one of:
- `{"json": normalized}` for `application/json`;
- `{"empty": true}`;
- `{"text": "..."}` for `text/*`;
- `{"sha256": hex, "len": n}` otherwise.

With `compare: "status"`, only `status`, the body kind and the top-level JSON keys are compared. The body kinds are checked in order: empty first (whatever the content type), then JSON (`{"invalidJson": text}` if it does not parse), then text, then binary.

**Normalizer** (identical rules in TS and Rust; both run `normalize-cases.json`, an array of `{ vars, input, output }`. The recorder checks them at start, and Rust has a `#[test]`-style trial):
1. **Strings.**
   - For every variable **except `PORT`, `HOST`, `REPO` and `NOTREPO`**, longest value first, replace occurrences of its value with `${NAME}`, and of its `encodeURIComponent` form with `${NAME|uri}`. `REPO`/`NOTREPO` are native-form (backslashes on Windows) while git prints `C:/…/repo`, so as patterns they would give `${REPO}` on macOS and `${ROOT}/repo` on Windows; the ROOT rule covers them. `HOST` is covered by the port rule. Object keys are normalized like strings.
   - `ROOT` is also matched in its native form, its backslash form and its non-canonical alias (macOS `/var/…` vs `/private/var/…`).
   - `PORT` is only replaced inside `127.0.0.1:<port>` and `localhost:<port>`.
2. **Paths.** A string that contains `${ROOT}` after step 1 has `\` replaced with `/`.
3. **Timestamps.** A number under one of the keys `updatedAt`, `since`, `lastActivityAt` or `resetsAt` becomes `0`. `null` stays `null`.
4. **File ids.** The string value of the key `fileId` becomes `"${FILE_ID}"`.

Details:
- **Poller** (port of `poller.ts`):

Write the token check fully qualified, `od_core::security::same_token`: od-server has its own `security` module, and a bare `security::same_token` would not resolve.
- **Produces:** the `/term` protocol below, which is the contract R4's app UI codes against.

**The protocol.** It is new; there is no Node counterpart.
- **URL.** `GET /term/<encodeURIComponent(agentId)>?token=<term_token>` with `Upgrade: websocket`.
- **Token.** `term_token` is 32 random bytes as lowercase hex (`getrandom`), made once per `serve` and exposed as `ServerHandle.term_token`. It is never sent over HTTP, so only an in-process client (R4) or a test knows it.
- **Two entry points, one checker.** Task 3's design handles upgrade requests before the normal chain, so a non-upgrade `/term/...` would never reach a `/term` handler and would fall to static. This task therefore:
  - extends the `/ws` pre-chain: an upgrade whose path starts with `/term/` goes to `term::handle`;
  - adds a `/term/` prefix arm to the normal dispatcher chain, **before** static and for any method, which calls the same checks and answers 400 `{"error":"websocket upgrade required"}` when there is no upgrade. TS served `index.html` for `GET /term/x`; that is a deliberate difference (Task 11 lists it).
- **Checks before the upgrade, in order:**
  1. The guard: 403 `{"error":"forbidden origin"}`.
  2. No upgrade header: 400 `{"error":"websocket upgrade required"}` (reached through the prefix arm).
  3. `od_core::security::same_token(&term_token, token or "")` false: 403 `{"error":"forbidden"}`.
  4. The id does not decode: 400 `{"error":"bad path"}`.
  5. `as_native()` is `None`, or `terminal_of(id)` is `None`: 404 `{"error":"unknown terminal"}`.
- **Server to client.**
  - The first frame is **Binary**: the `attach` snapshot (the serialized screen).
  - Then Binary frames carry the raw output chunks, in order.
  - When the agent exits, any queued output is sent first, then **Text** `{"type":"exit","code":<u32 or null>}`, then Close 1000.
- **Client to server.**
  - **Binary** frames are raw input bytes, passed to `pty.write(id, bytes)`.
  - **Text** frames are JSON:
    - `{"type":"input","data":"<string>"}` writes the UTF-8 bytes;
    - `{"type":"resize","cols":<1..=1000>,"rows":<1..=500>}` calls `pty.resize`; a value outside that is ignored, because the screen allocates rows × cols cells. `PtyHost::resize` applies the same limits (`MAX_COLS`, `MAX_ROWS`) and also ignores sizes under 2;
    - client messages and frames are capped at 1 MiB;
    - anything else is ignored.
  - A write error (`terminal_not_writable`) is treated as an exit with `code: null`.
- **Lifetime.**
  1. On upgrade, take `mute = pty.mute_replies(id)`. If it is `None`, send the exit message and close.
  2. Subscribe `on_exit` filtered by id, sending into a oneshot.
  3. `attach(id, push)`. The push goes into a bounded `mpsc::channel::<Vec<u8>>(cfg.term_buffer)` (default 1024) with `try_send`, and the queued bytes are counted (an `AtomicUsize`, freed on receive). On `Full`, or past 8 MiB queued, set a flag and close the socket with code 1013 and reason `slow consumer`, because the client must reattach for a fresh snapshot.
     On exit, output still arriving is forwarded until the stream ends (at most 2 s), then the exit message; the whole exit path, and every exit-message send, is capped at 10 s.
  4. `attach` returning `None` means the agent is gone: send the exit message.
  5. After subscribing, if `!pty.has(id)`, take the exit path. An agent that has already exited never fires `on_exit`.
  6. The mute, the attach subscription and the exit subscription are dropped together when the socket task ends, however it ends.
- **Clients.** Several clients may attach to one agent at once; each holds its own mute.
