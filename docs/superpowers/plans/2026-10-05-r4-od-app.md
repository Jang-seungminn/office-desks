# R4: od-app (Gongbang desktop app v1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship **Gongbang (공방)** v1, a Tauri 2 desktop app that runs od-core and od-server in-process on a random loopback port. Its UI has three parts:
- a sidebar: projects → worktrees → agents, with add project, new work, add agent, stop agent and remove worktree;
- tabs of live agent terminals over `/term` (xterm.js with WebGL, fit and unicode11), plus one optional split;
- a 🏢 사무실 button that opens the unchanged web office in its own window.

`cargo tauri build` (through the npm `@tauri-apps/cli`) produces a macOS `.app` and a Windows NSIS installer in CI. A Playwright E2E checks the app UI against the same in-process server.

**Architecture:**
- **Same origin, no new trust.** The app UI is a Vite build (`app/dist`) embedded in the app binary. od-server serves it under `http://127.0.0.1:<port>/app/` (new `ServerConfig.app_assets`). The main window loads that URL, so every `fetch`, `/ws` and `/term` call is same-origin, and the guard in `security.rs` is **not changed**.
  - Tauri IPC is the one channel the page has into Rust. It carries `term_config` (port and `/term` token), `pick_folder` (the native folder picker) and `open_office`.
  - IPC is granted at runtime by a capability scoped to window `main` and the exact remote URL `http://127.0.0.1:<port>/app/*` (Decision 1).
- **Core in-process.** The binary is `gongbang` (package `od-app`).
  1. `main()` first dispatches `hook-relay`.
  2. It builds its own tokio runtime and hands it to Tauri (`tauri::async_runtime::set`).
  3. It starts the server on port 0 with `create_backend(Some(BackendKind::Native), …)`.
  4. It runs the Tauri event loop.

  `RunEvent::Exit` blocks on `ServerHandle::shutdown()`, which disposes the agents. Closing the main window quits the app.
- **Testable seams.**
  - `od_app::core` (start, config) and `od_app::nav` (URL policy) are pure Rust, with no Tauri types, and are tested with `cargo test`.
  - The UI talks to the host only through `app/src/host.ts`. The E2E replaces it with an init script that fakes `window.__TAURI_INTERNALS__.invoke`.
  - The E2E harness is a Rust example. It calls the same `od_app::core::start` on a scratch world with the R2 fake agent.
- **Web office untouched.** No file under `web/` changes. The 🏢 사무실 window loads `http://127.0.0.1:<port>/` exactly as a browser does.

## Decisions

1. **Serve the app UI from od-server's own origin (`/app/`); do not add `ServerConfig.allowed_origins`.**
   - Tauri's custom-protocol origins are shared by **every** Tauri app on the machine:
     - `tauri://localhost` on macOS;
     - `http://tauri.localhost` on Windows;
     - `https://tauri.localhost` with `useHttpsScheme`.

     These were checked in tauri 2.12.1 (`webview/mod.rs` `is_local_url` tests, `protocol/tauri.rs`, `app.rs:342`). Allowlisting them would let any other Tauri app's webview call our API, and that API types into terminals.
   - Allowlisting would also mean adding CORS headers and an `OPTIONS` preflight (`/api/*` answers 405 to `OPTIONS` today). It would need a scheme exception (`is_allowed_request` accepts `http` only) and an exception for `Sec-Fetch-Site: cross-site`. Each is a new hole in a guard that R2 pinned against Node.
   - Same-origin needs none of this. The guard, CORS and contract fixtures stay as they are.
   - **The cost:** IPC from a remote URL. Tauri 2 refuses app commands from a non-local origin unless a capability with `remote` grants them (`webview/mod.rs`: "remote content can never reach custom commands unless an explicit `remote` capability has been configured"). So the app declares its commands in an app manifest (`tauri_build::AppManifest::new().commands(&[...])`, which generates `allow-term-config` and the others). At startup it adds one capability with `CapabilityBuilder::new("app-ui").remote(format!("http://127.0.0.1:{port}/app/*")).local(false).window("main")` and those three permissions, using `Manager::add_capability`.
   - Pinning the port at runtime means no other local server, and no other path on ours (the web office at `/`), can use the IPC. A scratch Tauri 2.12.1 app with exactly this API was built with `tauri build --bundles app` on 2026-10-05 and produced `Gongbang.app` without warnings.
2. **The UI gets the `/term` token from the Tauri command `term_config`.** It returns `{ port, token }` to window `main` on the `/app/` origin only.
   - The token is never in an HTTP response: not in the HTML, not in an asset, not in a header.
   - The page sends it only as the `/term` upgrade's `token` query parameter (the R2 protocol, loopback only, `Referrer-Policy: no-referrer`).
   - The office window is created by Rust, not by `window.open`, so it has no handle to the main window.
   - Tests pin this: Task 3's `token_is_never_served` and Task 9's "never serves the token".
3. **App UI stack:** Vite + TypeScript + xterm.js in `app/`, an npm workspace next to `web/` and `bridge/`. Plain DOM modules, with no framework, like `web/`.
4. **E2E: Playwright against the UI served by a Rust harness.** The harness (`cargo build -p od-app --example e2e_harness`) runs the same `od_app::core::start` on a scratch world, and IPC is faked by an init script.
   - Chromium runs on both OSes. WebKit also runs on macOS, as the nearest stand-in for WKWebView.
   - `tauri-driver` was rejected: it has no macOS (WKWebView) support, and the macOS bundle is the one the user runs daily.
   - The real Tauri window (IPC from the remote origin, the folder picker, the menu, ⌘Q disposal, WebView2 accelerators) is covered by a **manual check** (Task 11), which the user runs.
5. **`hook-relay` first.** `main()` checks `args_os().nth(1) == "hook-relay"` before the runtime, the core or Tauri start, and exits with `od_core::native::hook_relay::run()`. That is the same as `crates/office-desks/src/main.rs`. The native backend's hook command is `<current_exe> hook-relay`, which for the app is `Gongbang.app/Contents/MacOS/gongbang` or `gongbang.exe`.
6. **Port 0.** The app always binds `127.0.0.1:0`, so it can never collide with 4317 or with a running Node or Rust bridge. The office window uses the bound port. There is no port flag in v1.
7. **Keyboard: the app takes ⌘ chords on macOS and Ctrl+Shift chords on Windows (a deliberate deviation from the spec's plain Ctrl).**
   - On Windows, plain Ctrl+T, Ctrl+B and Ctrl+W are terminal keys that the agents use:
     - Claude Code: Ctrl+T toggles the todo list, Ctrl+B backgrounds a command;
     - readline: Ctrl+W deletes a word;
     - Ctrl+\ is SIGQUIT.

     Taking them would break the agents.
   - Windows terminals already use Ctrl+Shift for this (Windows Terminal: Ctrl+Shift+T and Ctrl+Shift+W).
   - On macOS, ⌘ never reaches a terminal, so the spec table holds as written.
   - Keys match on `KeyboardEvent.code` (`KeyT`, `Digit1`, `Backslash`), so a Korean IME (`key === 'ㅅ'`) does not break them.
   - One capture-phase `keydown` listener on `window` handles them before xterm's textarea sees them.
   - **This needs the user's OK** (see "Needs the user").
8. **macOS menu replaced.** Tauri's default macOS menu has File → Close Window on ⌘W (`menu/menu.rs` `Menu::default`), which would close the window before the page sees ⌘W. The app installs its own menu:
   - app menu: about, hide, hide others, quit;
   - 편집: undo, redo, cut, copy, paste, select all. These keep ⌘C and ⌘V working in xterm;
   - 윈도우: minimize, fullscreen.

   Windows has no menu.
9. **CSP for `/app/` only:** `style-src 'self' 'unsafe-inline'` and `connect-src 'self' ipc: http://ipc.localhost`.
   - xterm 6 writes `<style>` elements with `textContent`: the viewport scrollbar in core, and the DOM renderer's theme and dimensions. `style-src 'self'` blocks those, so the DOM renderer (the WebGL fallback) would lay out wrong.
   - Tauri's IPC first `fetch`es `ipc://localhost` (macOS) or `http://ipc.localhost` (Windows), and falls back to `postMessage` with a console warning when `connect-src` blocks it (`scripts/ipc-protocol.js`).
   - Inline styles cannot run script. `script-src 'self'`, `img-src` and the rest are unchanged, and `/` (the web office) keeps R2's CSP byte for byte.
10. **Bundles.** macOS: `--bundles app`. Windows: `--bundles nsis`. The identifier is `io.github.jangseungminn.gongbang`, `productName` is `Gongbang` and `mainBinaryName` is `gongbang` (verified in the scratch build). An identifier ending in `.app` makes the CLI warn, so it is not used.
11. **No `beforeBuildCommand`.** It runs through a shell. CI builds `web/dist` and `app/dist` explicitly and asserts both `index.html` files exist before `tauri build`. `crates/od-app/build.rs` also panics in a release build when either is missing, because rust-embed would silently embed nothing (PARITY's R6 note).
12. **No `frontendDist`.** Windows are created in code with `WebviewUrl::External`. tauri-codegen embeds an empty asset set when `frontendDist` is `None` (`tauri-codegen-2.7.1/src/context.rs`), and the scratch `tauri build` passed this way.

## Global Constraints

- **Platforms.** macOS and Windows are first-class.
  - The CI `rust` job runs `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` on both. It now also compiles od-app (Tauri).
  - The new CI `app` job runs the Playwright E2E and `tauri build` on both.
  - Linux is not a target. The workspace member `crates/od-app` needs webkit2gtk to build there. The README says so and gives `cargo test --workspace --exclude od-app` for Linux developers.
- **No shell.** Every process gets an argv array:
  - Rust uses `std::process::Command`;
  - Node uses `child_process.spawn(file, args)` without `shell: true`.

  Never `sh -c`, never `cmd /c`, never a Tauri `beforeBuildCommand`. `tauri-plugin-opener`'s `open_url` uses `/usr/bin/open <url>` (argv) on macOS and `ShellExecuteW` on Windows. It is called only with an `http`/`https` URL that `nav::new_window` returned `External` for.
- **Ports.**
  - Never use ports 4317, 4318, 4319 or 4320 anywhere: not in code, tests, scripts or the E2E.
  - The app and every test bind `127.0.0.1:0`. Tests assert that the bound port is not in `4317..=4320`.
  - The R2 security unit tests use the literal `4318` inside header strings only. They bind nothing and stay as they are.
- **Scratch only.** Never read or write the user's `~/.office-desks`, `~/.claude` or `~/.codex`, and never touch Orca processes.
  - Rust tests and the E2E harness pass a scratch env map: `HOME`, `USERPROFILE`, `TMPDIR`/`TMP`/`TEMP`, `CLAUDE_CONFIG_DIR`, `OFFICE_DESKS_HOME`, `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM=1`, with `PATH` = scratch `bin` + git's own dir.
  - They also pass a scratch `ServerConfig` (`upload_dir`, `commands_home`, `org_file`, `awards_file`, `assets` and `app_assets` all inside the scratch root).
  - The only agent on the scratch PATH is the R2 fake `claude` (a copy of the test or harness binary). A preflight refuses to run if another agent name resolves.
- **Process discipline.** Kill only PIDs you started.
  - Tests record agent PIDs from the fake agent's `agents.jsonl` and kill only those, and only on failure (a `PidGuard`).
  - Playwright kills only the harness PID it spawned, and only if it does not exit within 15 s of stdin closing.
  - Never `pkill`, `killall`, `taskkill /IM`, or kill by name or pattern.
  - The app's own shutdown disposes only its `PtyHost` children.
- **Security.**
  - The server binds 127.0.0.1 only.
  - The R2 guard (`is_allowed_request`) is unchanged.
  - `/term` and hooks keep their constant-time tokens.
  - The `/term` token travels by IPC only (Decision 2).
  - The IPC capability is window `main` + `http://127.0.0.1:<port>/app/*` only.
  - The main window may only navigate inside `/app/`. The office window may only navigate on the same origin outside `/app/`. External `http`/`https` links open in the OS browser; anything else is denied.
- **Korean UI strings** in the app, in the web's tone (`web/src/panel.ts`, `web/src/hireDialog.ts`). The exact strings are in Task 6. The window title is `Gongbang`, and the office window title is `🏢 사무실 — Gongbang`.
- **Web untouched.** No file under `web/` changes. `bridge/` changes only by having `app` read `bridge/src/model.ts` types (no edit).
- **Commits.** Each task ends with at least one commit. The message is a subject, a blank line, then exactly:

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_013wdfUqZP1py6R116oZnY8V
  ```

  Write the message to a file in the scratchpad and run `git commit -F <file>`. Pushing `Jang-seungminn/r4-app` is allowed; never push another branch.

## Review Focus

1. **Windows users pressing Ctrl+T, Ctrl+B, Ctrl+W, Ctrl+R or Ctrl+\ inside Claude Code.** They expect the agent to get the key, not the app.
   - App shortcuts are Ctrl+Shift+…, matched on `code`, so a Korean IME in Hangul mode does not break them.
   - Pinned by Task 8's `appAction` table:
     - Ctrl+T, Ctrl+W, Ctrl+B and Ctrl+\ are `null` on Windows;
     - Ctrl+Shift+T with `key: 'ㅅ'` is `newWork`;
     - ⌘T on macOS is `newWork` and Ctrl+T on macOS is `null`.
   - Also pinned by Task 9's E2E, which presses the platform chord.
2. **Quitting with agents running.** People expect no orphaned `claude` processes after ⌘Q, closing the window, or a crash of the UI page. ⌘W must close a tab, never the window.
   - Pinned by Task 3's `shutdown_disposes_agents` (PID gone after `Core::shutdown`).
   - Pinned by Task 9's global teardown: every agent PID is gone after the harness exits on stdin EOF.
   - The ⌘Q, close-window and ⌘W wiring is checked by hand in Task 11.
3. **A big paste or a burst of input.** It must arrive whole and never close the socket. The server caps a client message at 1 MiB, and the PTY input queue is unbounded.
   - Pinned by Task 7's `TermSocket` test: a 3 MiB paste goes out as 48 binary frames of ≤ 64 KiB, in order.
4. **An agent that exits, is stopped, or falls behind while its tab is open.** The person expects a Korean banner, not a blank or frozen pane. A 1013 slow-consumer close must reattach with a fresh snapshot.
   - Pinned by Task 7's `TermSocket` tests for the exit message, 1013 (reset, then reconnect), 1001 and a handshake failure.
   - Pinned by Task 9's "stop asks first" E2E.
5. **Removing a worktree that cannot go:** the main checkout, one with agents, or a dirty one. The person expects the Korean reason and nothing deleted.
   - Pinned by Task 1's status mapping (409 with `main_checkout`, `has_agents` and `dirty`) and the native `lifecycle` trial (`has_agents`, then success, then 404).
   - Pinned by Task 6's sidebar test, which shows the error in a toast.
   - Pinned by Task 9's E2E, which tries to remove the worktree while its agent runs.

**Files:**

**Interfaces:**

- **Produces:**
  - `tabs.ts`, `termClient.ts` and `termView.ts` as in the Public API;
  - `class Workspace { constructor(root: HTMLElement, cfg: TermConfig); open(desk, agent): void; close(agentId?: string): void; switchTo(index: number): void; toggleSplit(): void; copy(): string; paste(text: string): void; prune(s: OfficeSnapshot): void }`. With no argument, `close` closes the active tab.

Details:
- **`tabs.ts`** (pure, immutable):
  - **`openTab`:** if the tab exists, make it active; else append it and make it active. If the new active tab equals `split`, set `split` to the previous active.
  - **`closeTab`:**
    - remove the tab;
    - if it was active, `active` becomes the next tab, else the previous, else `null`;
    - if it was `split`, `split = null`;
    - if `active === split`, `split = null`.
  - **`switchTo(i)`:** if `i < tabs.length`, `active = tabs[i].agentId`; if that equals `split`, `split` becomes the old `active`. An index out of range is a no-op.
  - **`toggleSplit`:**
    - with `split` set → `split = null`;
    - with fewer than 2 tabs → unchanged;
    - else `split` = the tab after `active`, or the one before when active is last.
- **`termUrl`:** `` `ws://127.0.0.1:${cfg.port}/term/${encodeURIComponent(agentId)}?token=${encodeURIComponent(cfg.token)}` ``. The page is on `127.0.0.1:<port>`, so this is same-origin and passes the guard.
- **`TermSocket`:**
  - **Setup:** `binaryType = 'arraybuffer'`. `status('connecting')`, then on open `status('open')`.
  - **Server frames:**
    - binary → `output(new Uint8Array(data))`;
    - text → parse JSON; `{type:'exit', code}` → `status('exited', code)` and no reconnect.
  - **Closes:**
    - `1013` → `reset()`, `status('reconnecting')`, and reconnect at once (at most 3 in a row without an open in between, then `status('failed')`);
    - `1001` → `status('closed')`;
    - `1000` after an exit → nothing more;
    - anything else before the first open → `status('failed')`;
    - anything else after an open → like 1013, with a 500 ms delay.
    - `close()` sets a flag so its own 1000 never reconnects.
  - **`input(data)`:** `new TextEncoder().encode(data)` is sent as binary frames of at most `INPUT_CHUNK` bytes each, in order. This keeps every frame under the server's 1 MiB cap. The unbounded PTY queue stays as PARITY says ("Later"). The client never sends more than it was given.
  - **`inputBinary(data)`:** `Uint8Array.from(data, (c) => c.charCodeAt(0) & 0xff)`, chunked the same way.
  - **`resize(cols, rows)`:** sends text `{"type":"resize","cols":c,"rows":r}` only when both are integers in `1..=1000` and `1..=500`, and different from the last one sent. After a reconnect, the last size is sent again on open.
  - **Before open:** input is dropped, not queued.
- **`TermView`:**
  - `new Terminal({ allowProposedApi: true, fontFamily: '"SF Mono", Menlo, Consolas, "D2Coding", monospace', fontSize: 13, lineHeight: 1.1, scrollback: 5000, cursorBlink: true, theme: { background: '#151210', foreground: '#efe6d8' } })`.
  - `loadAddon(new FitAddon())`, `loadAddon(new Unicode11Addon())`, then `term.unicode.activeVersion = '11'`.
  - `term.open(host)`. Then try `const gl = new WebglAddon(); gl.onContextLoss(() => gl.dispose()); term.loadAddon(gl)` and catch: the DOM renderer is the fallback, and the app CSP allows its `<style>`.
  - **Wiring:** `term.onData → socket.input`, `term.onBinary → socket.inputBinary`, `term.onResize → socket.resize`. `output → term.write(bytes)`, and `reset → term.reset()`.
  - **Status banners** inside the pane (`<div class="term-banner">`):
    - `reconnecting`: `다시 연결하는 중…`;
    - `exited`: `에이전트가 종료됐어요 (코드 {code ?? '알 수 없음'}) — 탭을 닫아 주세요`;
    - `closed`: `공방이 닫히는 중이에요`;
    - `failed`: `터미널에 연결하지 못했어요 — 에이전트가 이미 끝났을 수 있어요`.
  - **Resizing:** a `ResizeObserver` on `host` calls `fit()` (debounced in one `requestAnimationFrame`).
  - **`dispose()`:** `socket.close()`, then `term.dispose()`. This detaches; the agent keeps running.
  - **`text()`:** the active buffer's lines `0..buffer.length`, `translateToString(true)` joined by `\n`.
- **`Workspace`:**
  - **Tab bar:** each tab is a `<button class="tab" data-agent>` with the title and `✕`.
    - Clicking the title activates it.
    - `✕` closes it (detach).
    - The tab's `title` attribute holds the shortcut index, `{shortcutLabel} {n}`, for the first 9.
  - **Panes:** with no split, `active` takes the full width; with a split, `active` is left and `split` is right, 50/50.
  - Each tab owns one `TermView`, created on first open and kept while the tab exists, so switching tabs does not reattach. Only `closeTab` disposes it.
  - **`prune(s)`:** for an open tab whose agent is no longer in the snapshot, mark the tab with a muted style. Do not close it: its banner already says the agent ended.
- **`debug.ts`:** if `isE2E()`, set `window.__gongbang = { text: (agentId) => workspace.text(agentId), tabs: () => state.tabs.map(t => t.agentId), active: () => state.active, split: () => state.split }`. Otherwise do nothing.
